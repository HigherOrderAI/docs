The Integrations tab in Administration wires HigherOrder into the document stores and support tools that produce evidence or metrics for vendor risk. Configuration lives at **Administration → Integrations**. Each integration is a per-tenant setup with its own auth, sync behavior, and status.

<Note>
**Where IdP / SSPM connectors live.** Okta, Google Workspace, and Microsoft Entra ID are configured under **Exposure → Connectors**, not in the Integrations tab. They feed the Drift Center. See [SSO](/administration/sso) for authentication configuration for those same IdPs on the login side.
</Note>

## What it does

Six integrations are wired end to end:

| Integration | Auth | Purpose |
|---|---|---|
| **SharePoint Online** | App-only (Entra ID app + client secret) | Sync vendor documents from a SharePoint site — optionally scoped to specific folders — into the standard document analysis pipeline |
| **OneDrive for Business** | App-only (shares the Microsoft 365 connection) | Sync vendor documents from specific users' OneDrive accounts — per-account grants, optionally scoped to folders — into the same pipeline |
| **Google Drive** | OAuth 2.0 (customer's own Google OAuth client) | Sync vendor documents from selected Drive folders — My Drive, shared folders, and shared drives — into the same pipeline |
| **Dropbox** | OAuth 2.0 (PKCE) | Scan Dropbox for contract files matching configured keywords and file types; index them into the Contracts inventory |
| **Jira** | OAuth 2.0 (PKCE) | Sync selected Jira projects; calculate SLA compliance, ticket velocity, and other vendor-related metrics |
| **Freshdesk** | API Key | Monitor selected Freshdesk support groups; track group-level SLA compliance and ticket metrics |

Each integration has a per-connector status card showing the current health, last sync time, and edit/disconnect controls.

## Health states

The connector health card can be in one of five states:

| State | Meaning |
|---|---|
| **Healthy** | Last sync completed successfully |
| **Pending** | Awaiting first sync |
| **Degraded** | Sync succeeded but returned partial errors |
| **Failed** | Sync failed completely |
| **Disconnected** | Not configured |

## SharePoint Online

**Purpose.** Sync vendor documents from a SharePoint Online site into HigherOrder. Synced files run through the standard document pipeline — each file is classified, matched to a vendor, added to the inventory, and analyzed.

Unlike the OAuth connectors, SharePoint uses **app-only credentials**: a Microsoft 365 admin registers an Entra ID application with the Microsoft Graph `Sites.Selected` permission and grants it read access to one specific site. There is no user sign-in and no redirect — HigherOrder can read only the site(s) explicitly granted, and access is revocable at any time by deleting the client secret or the site grant. The full admin walkthrough (including the per-site grant, which is a separate step from admin consent) is in the SharePoint Integration Setup Guide.

<Frame caption="Administration → Integrations: the connected SharePoint integration">
  <img src="/images/screenshots/sharepoint/01_management.png" alt="SharePoint integration management view" />
</Frame>

### Setup

<Steps>
  <Step title="Register an Entra ID app">
    A Microsoft 365 admin registers a single-tenant app, adds **Microsoft Graph → Sites.Selected** (Application) with admin consent, creates a client secret, and grants the app **Read** on the specific SharePoint site. Once the site URL is entered in the wizard, the grant panel shows two ready-to-paste **Graph Explorer** steps — fetch the site ID, then post the read permission — derived from the site-collection root, so the commands are correct even when the pasted URL points at a subsite or folder.
  </Step>
  <Step title="Connect">
    In HigherOrder → Administration → Integrations, open **SharePoint Online** and enter the **Directory (tenant) ID**, **Application (client) ID**, **Client secret** (with its expiry date, so HigherOrder can warn before it lapses), and the **site URL**. Use **Test connection** to verify.
  </Step>
  <Step title="Scope and sync">
    By default the whole site syncs. To narrow it, open **Edit configuration** and tick folders in the live folder browser — a ticked parent covers everything beneath it, and deep paths can be added by URL. The picker echoes the resolved site ("Connected to …") and where access was granted, and warns if the URL matched only the tenant root site — so a mis-typed subsite URL is caught at setup, not after a wrong-site sync. Then **Sync now**.
  </Step>
</Steps>

### Sync behavior

- **File types**: PDF, Word (`.doc`, `.docx`), Excel (`.xls`, `.xlsx`), and CSV by default; plain text available as an option. Up to 50 MB per file, 250 files per run.
- **Manual sync** — runs on **Sync now**; there is no scheduler for SharePoint yet.
- **Change detection** — unchanged files are skipped on re-sync; an edited file re-ingests as a new revision.
- **Sync report** — each run reports per-folder counts (found, new, unchanged, skipped) and names any selected folder that no longer exists. A single failed file is recorded and skipped; it never fails the run.
- **Secret handling** — the client secret is encrypted at rest and never displayed after entry (shown only as a masked hint). Rotate it any time from Edit configuration.

## OneDrive for Business

**Purpose.** Sync vendor documents from specific users' OneDrive for Business accounts into HigherOrder — for teams whose vendor evidence lives in individual drives rather than a shared SharePoint site. Synced files run through the same document pipeline as SharePoint: classified, matched to a vendor, added to the inventory, and analyzed.

OneDrive **shares the Microsoft 365 connection with SharePoint**. If SharePoint is already connected, the OneDrive setup shows "Using your existing Microsoft 365 connection" — no new app registration, no new permission, no new admin consent. The only OneDrive-specific step is granting the app read access to each OneDrive account you want in scope, because every OneDrive for Business is technically its own SharePoint personal site and the `Sites.Selected` permission is deny-by-default: the app can read **only** the accounts you explicitly grant, never the whole tenant.

<Frame caption="Administration → Integrations: the connected OneDrive integration, with one verified account and its latest sync">
  <img src="/images/screenshots/onedrive/01_management.png" alt="OneDrive for Business management view" />
</Frame>

### Setup

<Steps>
  <Step title="Connect">
    Open **OneDrive for Business** under Document Storage. Reuse the existing Microsoft 365 connection, or enter app-only credentials (Directory ID, Application ID, client secret) for a single-tenant Entra ID app with the **Microsoft Graph → Sites.Selected** application permission — the same registration the SharePoint integration uses. Pick the file types to sync and click **Connect OneDrive**.
  </Step>
  <Step title="Add accounts and grant access">
    In the management view, add each OneDrive account by the user's email (UPN) or by pasting their OneDrive URL. For every pending account, the **Grant read access** card shows two ready-to-run Graph Explorer steps (run by a Microsoft 365 admin, once per account). Then click **Verify** on each account — or **Verify all**. Each account shows its grant state: *Grant pending*, *Access verified*, or *Access failed*.
  </Step>
  <Step title="Scope and fetch">
    By default each verified account syncs its entire OneDrive. To narrow it, open **Edit configuration** and tick folders in the folder browser — the tree is rooted at the granted accounts, a ticked parent covers everything beneath it, and deep paths can be added by URL. Then **Fetch now**.
  </Step>
</Steps>

<Frame caption="Edit configuration: the folder browser rooted at granted accounts, with per-account folder scope">
  <img src="/images/screenshots/onedrive/02_folder_picker.png" alt="OneDrive folder picker with account-rooted folder tree" />
</Frame>

### Sync behavior

- **Scope is per account** — an account with folders ticked syncs only those folders; an account with nothing ticked syncs its entire OneDrive.
- **File types**: PDF, Word (`.doc`, `.docx`), Excel (`.xls`, `.xlsx`), and CSV by default; plain text available as an option. Up to 50 MB per file, 250 files per run — a capped run continues where it left off on the next fetch.
- **Manual sync only** — runs on **Fetch now**; there is no scheduler. Sync is strictly read-only: the platform never writes to OneDrive.
- **Change detection** — unchanged files are skipped on re-fetch, so a second run is cheap.
- **Sync report** — each run reports per-account-and-folder counts, vendors added, and files skipped (with reasons), and flags vendors created from a single document as worth a duplicate check.
- **Removing an account** removes its folders from scope but keeps already-synced documents. **Disconnecting** removes the connector and its account list; the shared Microsoft 365 credentials are deleted only when the last connector using them is removed.

## Google Drive

**Purpose.** Sync vendor documents (SOC 2 reports, VAPT reports, questionnaires, DPAs, policies) from Google Drive into HigherOrder. Synced files run through the same document pipeline as SharePoint and OneDrive: classified, matched to a vendor, added to the inventory, and analyzed.

Google Drive uses **your own Google OAuth client**: an admin creates an OAuth client in their Google Cloud project and signs in with the Google account whose Drive holds the documents. HigherOrder requests read-only Drive access and reads **only the folders you select** — the folder restriction is enforced by the platform, the same model as SharePoint's folder scoping. Marking the OAuth consent screen *Internal* (Google Workspace) keeps the app entirely inside your organization, with no Google verification required. The full admin walkthrough is in the Google Drive Integration Setup Guide.

### Setup

<Steps>
  <Step title="Create a Google OAuth client">
    In your Google Cloud project, enable the **Google Drive API** and create an OAuth client of type **Web application** with the redirect URI shown in the HigherOrder connect dialog. Mark the consent screen **Internal**.
  </Step>
  <Step title="Connect">
    In HigherOrder → Administration → Integrations, open **Google Drive**, enter the **Client ID** and **Client secret**, and click **Connect Google Drive**. You are redirected to Google to sign in and approve read-only access, then returned to HigherOrder.
  </Step>
  <Step title="Select folders and fetch">
    Pick one or more folders in the folder browser — My Drive, folders shared with you, and shared drives are all browsable — or paste a folder link from Google Drive. A ticked parent covers everything beneath it. Then **Fetch now**.
  </Step>
</Steps>

### Sync behavior

- **Folder-scoped by design** — at least one folder must be selected before a fetch runs; there is no whole-account sync.
- **File types**: PDF, Word (`.doc`, `.docx`), Excel (`.xls`, `.xlsx`), and CSV by default. Google-native files are converted on the way in: Docs arrive as Word, Sheets as Excel, Slides as PDF. Up to 50 MB per file, 250 files per run — a capped run continues where it left off on the next fetch.
- **Manual sync only** — runs on **Fetch now**; there is no scheduler. Sync is strictly read-only: the platform never writes to Google Drive.
- **Change detection** — unchanged files are skipped on re-fetch, so a second run is cheap.
- **Sync report** — each run reports per-folder counts, vendors added, and files skipped (with reasons: unsupported type, too large, shortcut outside the selected folders), and names any selected folder that no longer exists.
- **Disconnecting** revokes HigherOrder's access at Google and deletes the stored credentials; already-synced documents and analyses are kept.

## Dropbox

**Purpose.** Pull contract files from a Dropbox account into HigherOrder as documents. Files matching the configured keywords and file types are indexed into the Contracts inventory and become available for extraction.

### Setup

<Steps>
  <Step title="Register a Dropbox app">
    Create an OAuth app in Dropbox and copy the Client ID and Client Secret.
  </Step>
  <Step title="Authorize">
    In HigherOrder → Administration → Integrations, click **Add Dropbox**, paste the Client ID and Client Secret, and complete the OAuth authorization.
  </Step>
  <Step title="Configure">
    Set the **Keywords** (comma-separated — e.g., `contract, agreement, sla, msa, addendum`), tick the **File Extensions** to include (`pdf`, `docx`, `doc`, `txt`), and pick a **Sync Schedule** (Manual, Daily, or Weekly).
  </Step>
  <Step title="Verify">
    Use **Test Connection** to confirm the credentials, and **Sync Now** to trigger the first scan.
  </Step>
</Steps>

### What lands in the product

Matching files appear as documents in the Contracts inventory and are queued through the standard extraction pipeline (contract analyzer, obligations, penalties, contacts).

## Jira

**Purpose.** Sync selected Jira projects into HigherOrder; calculate SLA compliance and ticket-velocity metrics per project. Used for vendor operational-risk signals.

### Setup

<Steps>
  <Step title="Register a Jira OAuth app">
    Create an OAuth 2.0 (3LO) app in Atlassian Developer console and copy the Client ID and Client Secret.
  </Step>
  <Step title="Authorize">
    In HigherOrder, click **Add Jira**, paste the credentials, and complete the OAuth flow.
  </Step>
  <Step title="Configure">
    Pick the **Projects** to sync from a checklist populated live from your Jira instance, set the **Sync Schedule** (Manual / Daily / Weekly), and toggle **SLA Tracking** on if you want per-project SLA metrics.
  </Step>
  <Step title="Verify">
    **Test Connection** confirms the credentials. **Calculate Metrics** runs the metric pipeline against synced issues on demand.
  </Step>
</Steps>

## Freshdesk

**Purpose.** Monitor selected Freshdesk support groups; track ticket metrics and group-level SLA compliance for vendors whose relationships are visible in your support queue.

### Setup

<Steps>
  <Step title="Get an API key">
    Copy an API key from Freshdesk (Profile Settings → API Key).
  </Step>
  <Step title="Connect">
    In HigherOrder, click **Add Freshdesk**, enter the **API Key** and your **Domain** (e.g., `acme.freshdesk.com`), and click **Connect**.
  </Step>
  <Step title="Configure">
    Pick the **Groups** to monitor from a list populated live from Freshdesk, set the **Sync Schedule** (Manual / Daily / Weekly), and toggle **SLA Tracking** on if you want per-group SLA metrics.
  </Step>
</Steps>

## Sync cadence

For Dropbox, Jira, and Freshdesk, the connector scheduler ticks every 30 seconds and dispatches any connector whose sync interval has elapsed. Daily and Weekly schedules are best-effort — sync fires on the next tick after the interval expires, not at a specific wall-clock time. Manual runs via **Sync Now** are dispatched immediately. SharePoint, OneDrive, and Google Drive are manual-sync only (see above).

## Limitations

- SharePoint folder selection is a filter within one granted site collection; a folder from a different site collection needs its own site grant and connection. The folder browser is available only after the connection is saved.
- OneDrive covers OneDrive for Business only — consumer OneDrive (`onedrive.live.com`) is out of scope. Each account needs its own one-time read grant, and a OneDrive that the user has never opened may not exist yet (OneDrive is provisioned on first use).
- Google Drive's consent screen shows read access to the whole Drive (that is how Google's read-only scope works); HigherOrder reads only the selected folders, and the setup guide explains the wording. Very large Google-native files can exceed Google's export limit and are skipped with a reason in the sync report.
- Dropbox indexes files it can see with the OAuth token's scope; files outside that scope are invisible.
- Jira and Freshdesk sync is read-only. HigherOrder does not create or modify tickets or issues.
- Access-token refresh is automatic for OAuth connectors; if a refresh fails (revoked scope, expired grant), the connector moves to **Failed** and requires re-authorization from the setup dialog.
- The connector catalog contains placeholders for **Salesforce** and **Vanta** — these do not yet have a working setup flow.
